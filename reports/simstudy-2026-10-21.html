Cycle-length simulation study

What it did, why, and what it found. Results as they stand on 2026-10-21; no second stage was run. The design and the rules for reading it were written down before any fit ran (_scripts/simstudy.R, header).

Short answer
  • The number of model stages we assume changes the cycle length we get. Fitting the same artificial data with 384 stages instead of 192 gave a shorter cycle length every time we could compare (12 of 12), by 0.55 h on average.
  • Where it could be measured, the model's error was within about ±1.2 h and usually too long, but the study was too small to pin it down further.
  • Holding the starting synchrony fixed does not work with 384 stages, even at its true value: those fits almost never settle (1 of 25).
  • Most of the design could not be read, because too few fits passed the convergence check. In particular, it does not tell us what assuming too few stages does.

1. Why we ran it

The project asks how long the parasite's blood-stage cycle is, and how much of the answer comes from modelling assumptions rather than from the data. Our fits to the real infection data give 41.2–41.8 h, depending on two modelling choices.

n_c, the number of stages. The model splits each parasite's cycle into n_c equal stages, and a parasite moves on from each stage after a random wait. With more stages, the random waits average out over more steps, so every parasite's cycle takes closer to the same time. A group of parasites that starts in step then stays in step for longer. n_c therefore sets how fast the infection's rise-and-fall pattern fades, as well as how finely the model resolves parasite age.

b_shape, the starting synchrony. How tightly bunched the parasites' ages are at the start of infection. Higher means more in step.

Blood samples start only at 72 h, after one and a half cycles. By then both how in step the parasites started (b_shape) and how fast they drift apart (n_c) show up only through how strong the rise-and-fall still is. The data constrain the two together, not each one separately.

What we knew before this study:

  • An earlier simulation, with 96 stages, found the model read the cycle length 1.97 h too long. Most of that came from having to estimate b_shape: fixing it at its true value removed 0.92 h.
  • 96 stages was later shown to be wrong for the real data (192 fits better, and 384 better still), so the real-data fits moved to 192 and 384.
  • With 384 stages, real-data fits with b_shape fixed failed to converge.

So three questions were open:

  1. How far off is the model at the stage counts we now use?
  2. Does the stage count we assume change the answer, and what happens if it is wrong?
  3. Does it matter how b_shape is handled (estimated or fixed), and how synchronous the start really was?

2. How a simulation study answers that

Real data have no answer key, so you cannot see the model's error by fitting them. A simulation supplies one:

  1. Choose a full set of "true" parameter values: each trial's cycle length, growth rate, starting parasite numbers, b_shape, and measurement noise.
  2. Use the model to generate an artificial dataset with the same 13 trials, the same 177 volunteers' series, and the same 1,130 sampling times as the real data. Then add random measurement noise of the size estimated from the real data.
  3. Fit the model to the artificial data exactly as we fit the real data.
  4. Compare the estimated cycle length with the true one we put in. Bias = estimate − truth, averaged over the 13 trials, in hours. Positive means the model reads the cycle too long.
  5. Repeat with 5 different random noise draws ("replicates"), to see how much the result moves by chance alone.

4. How a fit is judged

What fitting produces. The fitting method (Bayesian sampling) does not return one best answer. It explores which parameter values are consistent with the data and returns a large collection of plausible values ("draws"). The cycle length we report for a fit is the average of its draws, the posterior mean.

Chains. The exploration is run 8 times independently ("chains"), each from a different starting point. Each chain spends 700 steps tuning itself and then records 500 draws.

The convergence check, R-hat, in steps:

  1. If all 8 chains have found the same answer, each chain's draws spread about as widely as all the draws pooled together.
  2. If one chain is stuck somewhere else, the pooled draws spread wider than any single chain's.
  3. R-hat is, roughly, the square root of the pooled spread divided by the typical within-chain spread. (The version used also splits each chain in half, which catches a chain that drifts.)
  4. R-hat = 1.00 means the chains are indistinguishable. Larger means they disagree.
  5. Project rule: R-hat must be below 1.05 for every quantity in the model. A fit that fails is not trusted, and its estimate is not used.

lp__ is the model's overall score for a set of parameter values: how well they fit the data, plus how plausible they were thought to be beforehand. Chains whose average lp__ differ widely are sitting in different places.

Reading rule. A cell is reported only if at least 3 of its 5 replicates pass the check. With fewer, there is too little to say. Both rules were fixed before any fit ran, so they could not be tuned to the results.

Paired comparisons. The same artificial dataset is fitted twice, for example with 192 and with 384 stages, and the two estimates are subtracted. The dataset's own random noise is common to both fits and cancels out. That makes a paired difference much more precise than comparing fits to different datasets.

5.4 Paired comparisons

Each dot is one replicate: the difference in estimated cycle length (averaged over 13 trials), hours, between two fits of the same artificial dataset, both passing the check. Dashed line: average of the dots. Row labels: truth · stages used to generate · true b_shape scale · how b_shape was fitted.

384 stages minus 192 stages (12 pairs).

All 12 are negative, from −0.10 to −1.49 h. This holds whether the data were generated with 192 stages (so 384 assumes too many) or with 384 (so 384 is correct and 192 too few). How unlikely is that by chance?

  1. If the stage count made no difference, each pair would be equally likely to come out positive or negative, like a coin toss.
  2. The chance that 12 tosses all land the same way is 2 × (½)12 = 1 in 2,048, about 0.0005. This is a sign test.
  3. Caveat: only pairs in which both fits passed the check are included. If passing were linked to the estimate itself, the 12 would not be a fair sample.

A possible mechanism, proposed earlier and not tested here: the model can produce the observed rise-and-fall either with strong oscillation and a short cycle or with weaker oscillation and a longer one. With fewer stages the oscillation fades faster, and earlier fits made up for it with a more synchronous start and a longer cycle. The result above fits that account.

b_shape estimated minus fixed at truth (9 pairs), same stage count.

6 of 9 are positive, from −0.18 to +1.36 h. Having to estimate b_shape lengthens the estimate, the same direction as the earlier 96-stage finding, but nine pairs are too few to confirm it.

6. Answers to the three questions

  1. How far off is the model at the stage counts we now use? Where the stage count is right and enough fits passed, the error is between −0.6 and +1.2 h, usually too long. The study cannot give a single, precise figure.
  2. Does the stage count change the answer, and what if it is wrong? Yes: assuming 384 stages instead of 192 shortens the estimate by about half an hour on the same data. What a wrong stage count does to the error against the truth is answered only for assuming too many (one readable cell, +0.40 h). Assuming too few is not measured.
  3. Does b_shape handling matter? With 384 stages, b_shape cannot be fixed, because the fits do not converge even at the true value. Estimating it probably lengthens the estimate (+0.33 h on average, 6 of 9 pairs), but this is not established. No dependence on the true synchrony is visible.

7. What it means for the analysis

  • Any reported cycle length must state its stage count. Changing it from 192 to 384 moves the estimate by about as much as the bias we are trying to measure.
  • The study does not say which stage count gives the less biased answer.
  • With 384 stages, b_shape has to be estimated. The earlier project decision to fix b_shape (at 400) was made with 96 stages and does not carry over. The convergence failures of fixed-b_shape real-data fits at 384 are what the model does even when correctly specified, not a sign that it misfits the real data.
  • No bias correction can be taken from this study for the real-data estimates of 41.2–41.8 h.

8. Limits

  • 500 draws per chain, half our usual length, chosen so that 8 chains gave the usual 4,000 draws in total. A second stage with 1,000 draws per chain was costed at about 4–7 days on half the cluster node, and not run.
  • Truth A comes from a 96-stage fit, which we now know is the wrong stage count. It serves only as a plausible set of values to generate from.
  • Paired comparisons include only pairs in which both fits passed.
